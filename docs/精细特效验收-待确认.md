# 对局内精细特效 · 验收记录

本记录原用于源码修改后的预览确认。用户现已要求打包完整包；当前包包含以下源码、素材、测试及录制工具。微信真机与线上验收边界仍以下文为准。

## 修改内容

- `src/battle-effects.js`：140–240ms 平滑走子，轻微抬起、细落点波纹；220ms 单面翻棋和扫光；集中接触光、最多12条非均匀金色碎光、薄冲击波；接触后目标缩小淡出；中央金色「吃」字；650ms 将军文字与王棋脉冲；终局收束；150ms 点选亮度；每秒一周期红光。
- `src/battle-timeline.js`（新增）：公开局面快照组成视觉队列。棋局立即响应输入，连续动作按序呈现；暂停冻结，恢复续播，结束释放临时状态。
- `src/fusion-effects.js`：目标格附近两条细弧汇聚、紧凑脉冲和扫光，350–550ms范围内结束；保留原合棋棋子 UI。
- `src/renderer.js`、`src/ui-v2.js`：保留静态棋盘/棋子缓存；环统一前景绘制，同一棋子只一个白环；红环与白环同用半径36、线宽4；只重绘有活动特效或低时提醒的场景；图片/特效字形在进入对局前准备。
- `src/controller.js`、`src/runtime.js`：删除旧动画期间的输入拦截；事件去重；连续追击按次序播放；一次网络轮询收到 firstHop 和第二跳时补齐已知第一跳，已看过的不重复；超时/认输等独立于上一手。
- `utils/audio.js`：仅新增旧对局音频队列清理，不修改既有 Audio.event 触发规则、语音文件和对应关系。修复终局后待播合棋分段继续播放的边界问题，背景音乐不受此清理影响。

## 保持不变

棋规、AI文件与难度、音效映射、按钮功能和布局、棋盘/棋子图片、阵营色、字体素材、表情图片及功能、云函数与配置均未修改。217个受保护文件进行了哈希检查，唯一差异是上述音频队列清理方法；原 Audio.event 函数文本逐字一致。

没有新增 PNG/JPG 素材；小规模字形缓存在启动时用现有 UI 字体生成，避免触发时解码大图。

## 实际录制的来源

`tools/record-realtime-effects.js` 运行当前项目真实 Runtime、Controller、game-engine 和 Canvas Renderer，由 `tools/recording/canvas-host.js` 适配本地微信 I/O。输入来自合法测试局面；走子调用真实点击处理与棋规，状态转换不是由录屏脚本伪造。使用真实 Date.now、真实定时器采集 Canvas，每帧保存实际时间戳，按时间戳导出 GIF/MP4。没有 AI 生成视觉素材，没有重画替代界面。

这属于本地真实代码的 Canvas 运行录制，不是微信开发者工具、手机真机或联网双人录像。录像顶部深色标题条仅为录像标注，不属于产品界面。GIF 和 MP4 为静音预览；声音通过真实音效事件函数及本地 API 播放请求日志检查，不能等同于微信设备的实际扬声器验收。

三段内容：

1. 点选、普通走子、上一步白环、吃子、吃子并将军、暗棋翻开、揭棋翻开、暗子被吃。
2. 普通合棋、将帅合棋、35ms连续输入的两跳追击、轰双吃。
3. 红方最后10秒、暂停/恢复、换边清红光、黑方最后10秒、合棋后超时与结算。超时后日志只出现 `25_超时判负.wav`，没有上一手合棋音频。

## 已验证

- 148项 Node 测试通过，0失败、0跳过，见 `precise-vfx-review/tests.txt`。
- 实际 Native Canvas：2种质量档 × 7种场景 × 8个时间点，共112帧，无渲染错误。低档将碎光减少为最多6条，并取消额外阴影层。
- 四玩法走子时序和公开身份保护；隐藏目标不提前翻面。
- 快速输入不拦截；两跳逻辑立即生效，视觉/音效事件均按序；网络合并轮询补全第一跳且不重复。
- 双吃有两个目标、一次动作事件；八种合棋均使用紧凑时序，三种将帅合棋语音文件名与旧版相同。
- 捕获区使用实际来源棋子的阵营与图形，接触前后只影响显示快照，不更改棋局数据。
- 白环去重、红白环同规格；静态缓存保留，效果尾帧完成后停止连续渲染。
- 将军与音效在同一事件落点时间触发一次；终局结果弹窗沿用现有计时逻辑。
- 手动暂停/恢复、真实重开处理、卸载、切后台及超过时限后回前台；超时清理上一手动画和待播音频，翻转或再次同步不重播。
